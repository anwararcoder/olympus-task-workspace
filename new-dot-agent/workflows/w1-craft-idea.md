# W1 — Craft Idea

**Input:** a repo dossier with ranked seams. **Output:** `{problem}-plan.md` containing the three
empirical gates' evidence. **Rules:** `rules/task-shape.md`, `rules/idea-crafting.md`,
`lessons/INDEX.md` (read first — never re-try a dead lever or dead shape).

1. From the dossier seams, draft 3 candidates. Run the kill questions (`task-shape.md` §5) on
   each, adversarially. A candidate that is a READ, compute-and-emit, or leaf shape dies here.
2. For each survivor: a FULL draft title + description ("Add ...") for the plagiarism preflight —
   the plagiarism judge compares how the DESCRIPTION is written, so a stub is the wrong input. Owner
   runs the platform uniqueness preflight EARLY, making the package valid with borrowed local
   unsubmitted patches (e.g. from a rejected task). Flagged similarity = pivot, not reword. A clean
   description ≈ a clean full task, so this is the only plagiarism gate the idea needs.
3. Select one. Execute the three empirical gates (`idea-crafting.md`):
   - **Gate A** cascade arithmetic (largest cascade and union vs the partial-reward bar),
   - **Gate B** validation spike (build the hardest fork in a throwaway worktree; MEASURE LoC),
   - **Gate C** naive-agent gauntlet (fresh strongest-model session, description+repo only;
     record where it cruised vs diverged). 
   Any gate failing = deepen (add the algorithm-forcing constraint / restructure to STATE shape)
   or return to step 1. Do not rationalize past a failed gate — that is the death spiral's door.
4. Write per-fork discoverability proofs (clause/signal → naive opposite → failing test →
   base-symbols observable). A fork without a writable proof gets redesigned now.
5. Write `{problem}-plan.md` per the output schema in `rules/idea-crafting.md`. Create `{problem-name}-ledger.md`
   (`rules/documentation-ledger.md`). The plan is immutable once W3 starts.

**Session pattern:** crafting and red-teaming are separate sessions. After the plan is drafted, a
FRESH session plays the skeptic with only the plan + repo: it must try to answer "yes" to every
kill question and attack each gate's evidence. Surviving that review = ready for W2.

Done when: plan exists with measured (not estimated) Gate A/B/C evidence, owner approves, and the
uniqueness preflight is clear.
