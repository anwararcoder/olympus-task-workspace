# Exhaustive fold for enclosed value families

Add a generated fold companion for families of immutable values. When a type annotated with `@Value.Enclosing` declares a nested abstract type with two or more nested `@Value.Immutable` implementations, the processor generates, in the enclosing type's package, a public interface named after it with the suffix `Fold`, carrying one type parameter for the result.

The fold interface declares one `case` method for each implementation of a family that receives a `fold` method, named `case` followed by the implementation's simple name, and, as its only default methods, a `fold` method for each such family type. An implementation that at least one other nested implementation extends is itself a family type and receives its own `fold` method.

Applying `fold` computes bottom-up. Before an implementation's case runs, the operation is applied to the values held by that implementation's attributes, including inherited ones, whose declared type is a family type of the same enclosing type that receives a `fold` method, and the case receives the value itself, declared as the nested type the case is named after, followed by those results, one parameter per such attribute in declaration order. A plain attribute contributes the result directly. An optional attribute contributes an optional of the result, in the attribute's own optional type, empty when the attribute is empty. A list, set, or multiset attribute contributes a list of the elements' results in the attribute's iteration order, a multiset repeating each element by its multiplicity. An array attribute contributes a list of the results in array order. A map whose values are a family type contributes a map from the same keys to their results, preserving iteration order; a multimap contributes a multimap the same way, preserving per-key multiplicity and order. A nullable attribute, whether a single value or a container, contributes null when it holds null, and otherwise folds by its shape as above. Attributes with no family involvement, and family values held in any other shape, such as a map key or a nested container, contribute no parameter.

Within one application of `fold`, the operation runs at most once per value it reaches: a value reachable more than once has its case run once, the result reused where it appears, while two separate values that compare equal are each folded on their own. Every case method is abstract. When implementations of a family extend one another, `fold` dispatches to the case of the value's most specific implementation. Passing a family-type instance that is not one of the generated implementations throws an `IllegalArgumentException`.

An enclosing type may declare several family types, and an implementation reachable from more than one family type has exactly one case. A nested abstract type with fewer than two implementations, and families outside an `@Value.Enclosing` type, receive nothing. A family type that declares its own type parameters gets no `fold` method; an implementation that declares its own type parameters but belongs to a family that does receive one still gets a case.
