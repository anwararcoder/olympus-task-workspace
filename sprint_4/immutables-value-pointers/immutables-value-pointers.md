# Pointers into Enclosed Value Families

Add generated pointers for families of immutable values. When a type annotated with `@Value.Enclosing` declares a nested abstract type with two or more nested `@Value.Immutable` implementations without their own type parameters, the processor generates in its package a public final companion named after the enclosing type with the suffix `Pointers`. Enclosing types without such a family, or whose such implementations, whether or not they belong to the family, do not all generate modified copies (the `with` methods), receive nothing.

A pointer is the companion's nested `Pointer`, converted to and from its string form by the companion's static `parse(String)` and `render(Pointer)`. The empty string is the root pointer; every other pointer writes steps preceded by `/`, and within a step `~0` stands for `~` and `~1` for `/`. Any other use of `~`, and any other string not starting with `/`, fails `parse` with a nested `MalformedPointerException`. Rendering a parsed pointer returns the original string, equal strings parse to equal pointers, and a pointer's `toString` is its rendered form. Steps may be empty.

The companion's static `resolve(Object, Pointer)` walks a root by a pointer to the addressed value. The root must be a generated implementation of the enclosing type without its own type parameters, whether or not it belongs to a family; anything else raises `IllegalArgumentException`. A step at an implementation selects an attribute of the value actually present, declared or inherited, whatever its position's static type. A step selecting a list or array attribute, or a map attribute with plain string keys, addresses the container as a last step; otherwise the following step is the key, or a zero-based index of digits, no sign or leading zeros. An optional attribute step addresses its content. Every other attribute is a whole value; no step applies below a value that is not itself such an implementation.

Failures are distinct: a nested `PointerMissException` for an absent attribute, an index past the end whatever number its digits form, an absent map key, an empty optional, or a step through null, whatever the shape of the attribute holding it; a nested `PointerTypeException` for non-index text where an index is required, or a step where none can apply. Resolving a null-holding position returns null.

The companion's static `update(Object, Pointer, UnaryOperator)` applies a `java.util.function.UnaryOperator` to the addressed value and returns a new root carrying its result. A result equal to the existing value returns the original root instance. Otherwise only the values along the pointer's path are rebuilt: everything off that path enters the new root as the very same instance; a rebuilt map keeps its iteration order and other entries; a rebuilt list or array keeps its other elements. A wrong-typed replacement for a scalar or container attribute, null anywhere but a nullable position, or a replacement root that is not such an implementation raises the type mismatch and leaves the root untouched. An update at or through a derived or lazy attribute raises the type mismatch. Set, multiset, multimap, sorted or non-string-keyed map, and primitive-element array attributes are whole values only: stepping below or updating them raises the type mismatch, and the operator runs only when the walk permits the update.
