# Configurable Collection Implementations

Allow a project to replace the built-in concrete types used when MapStruct creates supported collection and map interface results. By default, configuration is read from `mapstruct.properties` at the root of the mapping compilation classpath. The `mapstruct.configurationFile` annotation processor option instead names another resource on that same classpath by relative path. Neither resource is resolved from the annotation processor's own classloader. That resource must exist when explicitly selected; without a default resource, the built-in choices remain in effect.

Entries have the form `mapstruct.collectionImplementation.<interface-qualified-name>=<implementation-qualified-name>`.

Parse the resource as a standard Java properties file. Equal duplicate entries are permitted. Unknown properties, unsupported interfaces, empty values, and conflicting duplicates fail compilation with a diagnostic that identifies the invalid key or value and its cause.

An implementation may be a source type in the current compilation. An implementation generated by another annotation processor in a later processing round is valid and must be used once it becomes available; one that never becomes available remains an invalid configured value. The implementation must resolve to a publicly accessible concrete class, be assignable to the named interface, have the same number of unbounded type parameters and preserve the interface type parameters, and expose a public no-argument constructor that declares no checked exceptions. When it also exposes a usable public `int` constructor, MapStruct must use that constructor with the source size as the initial capacity.

The rule applies to every mapping form, including collection or map values copied directly into bean properties and collection results materialized from streams. In each case, the configured choice replaces the built-in only when MapStruct constructs that exact supported interface result; construction follows the rule above, and an applicable object factory still wins.
